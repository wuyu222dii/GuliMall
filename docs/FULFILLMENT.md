## 页面与接口

| 方法与网关路径 | 用途 |
|---|---|
| GET `/api/admin/order/order/list` | 管理员按完整 `orderSn`、`status` 查询；`page`、`limit` 分页，默认最新订单优先 |
| GET `/api/admin/order/order/info/{id}` | 管理员查看订单、商品和地址快照、物流与操作历史 |
| POST `/api/admin/order/order/{id}/ship` | 管理员提交 `deliveryCompany`、`deliverySn` 并发货 |
| GET `/api/order/mine` | 本人订单列表；客户端 memberId 不参与身份判断 |
| GET `/api/order/mine/{id}` | 本人订单、商品/地址快照、物流和历史 |
| POST `/api/order/mine/{id}/receive` | 本人确认已发货订单收货 |
| POST `/api/order/mine/{id}/cancel` | 本人取消待付款订单，或重新检查已发起的关闭 |

管理页 `/admin/orders` 提供完整订单号与状态组合筛选、详情、物流填写及原有支付/消息重试。会员页 `/member/orders` 提供订单详情、物流、历史、取消和收货确认。取消和收货先显示确认内容，失败时保留原订单并提示查询后重试。

接口沿用 R / PageUtils。分页为 1–1,000,000，单页 1–100 条；订单号为完整 32 位小写十六进制，状态 0–9。非法参数返回 400，未登录 401，越权 403，不存在 404，状态冲突 409。业务服务独立验证 Session 与 CSRF，直接访问订单服务也不能绕过权限；会员写操作可携带 `X-Cart-Owner`，会话已切换时拒绝操作。

## 状态与幂等

正常履约：`0 待付款 → 1 已支付 → 2 已发货 → 3 已完成`。发货要求 status=1、inventory_status=1 且已保存支付交易号，数据库条件更新再次检查门禁。未支付、扣减未完成、创建/关闭中、已关闭和异常付款均不能发货。

发货在同一订单本地事务中锁订单、更新状态/物流/发货时间并保存历史。物流公司去除首尾空格后为 1–64 字符，拒绝控制字符；运单号为 1–64 位字母、数字或连字符。已发货或已完成订单重放相同物流返回原结果，保留原发货时间；不同物流返回 409，不覆盖原记录。首版不支持改运单或拆包发货。

收货在同一事务内校验会员归属，并条件更新 2→3、confirm_status=1、receive_time，写一条历史。本人重复确认已完成订单返回原结果，时间和库存不再次变化。其他会员即使传入本人会员 ID 或伪造请求头也不能收货。

订单详情包括下单时的商品/单价/数量/金额与地址快照，修改商品或地址不覆盖旧订单。操作历史按写入顺序展示。旧订单、明细、支付流水及操作历史管理 CRUD 不能直接伪造或删除业务记录。

## 取消与付款竞争

取消先锁订单，将待付款 0→8 的关闭意图和会员操作历史一起提交，然后复用阶段 7 的支付查询/关闭流程，不在本地事务内执行远程请求。状态 8 或已关闭 4 的重试不重复创建取消历史；已支付、已发货、已完成和异常订单拒绝取消。

支付已成功时，以验签通知或可信查询确认付款，保留已支付订单并进入扣减流程，取消不会释放其库存。明确未付款关闭后，4 与 STOCK_RELEASE 事件同事务保存，库存服务幂等释放。支付/关闭未知、网络故障、未配置沙箱或已签发表单却一直查无交易时保留 8 与库存锁定，后续扫描/人工重试继续确认，不显示虚假取消成功。

付款与取消共用订单行锁和阶段 7 的库存决策：付款先确认则扣减；关闭先确认后又收到付款则记异常 9，不恢复正常履约。消息重复或回执重试不重复释放，迟到付款不自动退款。边界和真实沙箱配置见 [PAYMENTS.md](PAYMENTS.md)。
