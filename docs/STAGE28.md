## 商品筛选及上下文

后台商品列表组合名称/编号、三级分类、品牌和状态；名称与编号同时显示。筛选及页码保存在 URL，可刷新、前进、返回和复制，编辑保存/新建查询成功后仍带原列表条件；返回列表恢复原页。空页超过最后页时更正页码。

复用现有商品列表接口：page 1–1,000,000、limit 1–100、key 最多 100 字，brandId/catalogId 为正编号，status 0–2。后端保留旧 catelogId 拼写及编号 0 表示全部的兼容调用。数字关键词匹配编号或名称，文字只匹配名称，不让 MySQL 隐式数字转换参与匹配；按编号倒序保证分页稳定。非法参数 400。

状态 0 显示“草稿 / 已下架”，1“已上架”，2“历史下架”。2 只兼容历史读取；原上下架服务仍只接受 0/1，不改写历史记录。分类或品牌选项加载失败时，原筛选编号和真实商品结果保留，单独提示名称未加载并允许重试；主查询失败不显示虚假的空结果。

## 管理订单独立详情

/admin/orders 保存 orderSn、status、page，提供清除。/admin/orders/:id 复用已有商品/地址快照、物流、历史、事件进度和安全重试；“返回订单查询”带回原筛选及页码。详情支持刷新、复制、重新登录回跳。登录目标只允许已知本机管理路由及合法查询，不接受外部、未知参数或哈希目标。

详情加载时清除原订单，晚到响应不能覆盖新订单；写操作捕获原订单和页面标识，结果不会串到其他订单。未付款和库存未确认不提供发货表单，服务端仍独立执行身份、CSRF、支付/扣减状态及条件更新校验；不存在订单明确提示，不能显示旧表单。普通会员不能读取管理详情或处理进度，隐藏按钮不作为权限依据。

## 同步任务

任务展示已有版本、次数、失败原因、next_attempt、updated_at，并可直接编辑对应商品。已同步项不展示无意义的下次失败重试时间。查询失败和操作失败分别保留，不把列表刷新成功当成重试成功；全量重建只说明任务已持久化，必须刷新核对各项结果。

同步页仍展示全部任务，商品筛选查询仅作返回列表上下文。分页总数与实际行使用相同 JOIN，历史孤立任务不会撑出空页；不删除孤立数据，不改同步执行与补偿规则，不提供强制改支付或库存状态的按钮。
