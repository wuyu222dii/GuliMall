## 入口与前置条件

```powershell
# 使用现有锁定依赖；先完成前端 npm ci、lint 和生产构建。
node gulimall-web/node_modules/@playwright/test/cli.js install chromium
# Microsoft Edge 需在本机已安装且允许启动独立的自动化临时配置。
./scripts/test.ps1 -Suite Browser
```

统一入口会先检查构建产物和锁定 Chromium，再实际启动/关闭无业务页面的临时 Edge。缺少依赖、构建或 Edge 启动失败时，在暂停常驻环境前拒绝；不静默改用另一浏览器，也不操作用户的日常 Edge 配置文件。

随后复用既有 Test 数据库真实身份检查、生产静态构建及同源 /api、独立模拟密钥和持久台账。全部测试串行执行、workers=1、不自动重试。运行期间暂停常驻商城，成功和失败都恢复调用前模式。不要与人工演示、其他验收或恢复任务并行。

## 四个场景

| 项目 | 场景 | 主要证据 |
|---|---|---|
| chromium | 完整交易第 1 轮 | 图片、双 SKU、采购、上架、注册、地址、搜索、购物车、付款、库存、发货收货、失败/取消、隔离和窄屏 |
| chromium | 完整交易第 2 轮 | 另建独立夹具，再次走完整页面链；不共享第一轮业务对象 |
| edge | 关键交易 | 页面登录/检索加购/付款/履约/收货/失败放弃/取消及刷新；会员订单和确认页归属隔离 |
| edge | 交互边界 | 375px Tab/Enter/Space、刷新确认、复制同一确认地址并发提交、服务端会话失效后的登录回跳、返回刷新及键盘取消 |

Edge 的商品与采购夹具通过受保护的真实业务接口准备；消费者交易及管理员发货通过页面操作。接口/SQL 只读核对订单与库存，不修改数据库业务状态，不拦截返回假成功。页面网络路由只拦截非本机地址。

会话失效通过另一标签退出，真正销毁共享服务端 Session，再让原页访问受保护接口得到 401；重新登录同一会员后恢复原提交。这不是自然等待 Session TTL 或人为改系统时间的证据。

窄屏用桌面 Edge 的 375px 视口，检查真实 Tab 焦点、Enter/Space 操作、确认按钮边界和页面无整体横向溢出。勾选等异步操作等待服务端确认，控件临时禁用后重新使用 Tab 到达，不用脚本强制 focus 或伪造点击代替键盘操作。它不代表实体手机、触摸或屏幕阅读器认证。

## 修复的同一确认多标签问题

原实现仅在提交时保存请求；新标签进入没有确认标识的 /checkout 会再次创建确认，并发提交会产生不同订单。仅依赖 sessionStorage 也不能保证新标签取得同一请求。

现在确认草稿在首次获取后保存，地址采用 `/checkout?confirmation=<确认编号>` 定位。复制该完整地址、刷新或重新登录均查询同一确认；后端仍从 Session 判断会员归属、重新算价并按原提交令牌防重。确认编号不作为登录凭据，其他会员访问返回 403。

提交前可以选择地址；提交或结果未知后保留原地址/请求。旧 sessionStorage 请求没有 submitted 字段时仍按已提交处理，不清空历史。购物车发生变动时，可显式“安全替换确认信息”；已存在订单时原接口返回该订单，不擅自新建。正常“开始下一次确认”仍是明确操作。

本轮保证复制同一确认地址的两个标签并发操作只生成一笔订单、锁一次库存。用户分别主动新建的不同确认仍是不同购买意图，不按同一购物车强制合并。
