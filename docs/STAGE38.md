## 环境与复现

实施前 Docker 和业务服务已停止。启动现有 Docker Desktop，核对原 `overlayfs` 镜像存储，恢复原 Compose 和常驻模拟环境，18 项诊断健康；没有初始化或删除数据库、卷、图片、签名密钥或支付台账。原 Demo 订单/地址快照、库存、采购业务字段及私有文件只读核对一致。

浏览器复现仅运行在实际库名校验通过的独立 Test 环境，故障使用真实写入后丢响应、请求中断及真实跨会员接口响应。原 70 项浏览器场景保持，新增场景分别统计。生命周期串行执行，成功和失败均恢复调用前的常驻模拟模式。

首轮复现脚本同时匹配页头和页面错误提示而停止，业务尚未修改；收窄测试定位后重新复现，失败证据单独保留。

修正后的复现轮在 Chromium/Edge 共 8 项通过，分别确认：真实加购丢响应后刷新仍可再次增量、全选第二项失败后服务端部分保存而界面仍全勾、数量草稿直接离开丢失、真实跨会员 403 后旧付款按钮可操作且仍在轮询。结果 `.tools/stage38-repro/*.json`，原复现代码与日志单独归档，不作为修复成功检查。

## 实现与边界

- 加购待核对标记绑定当前购物车身份与原 SKU/数量；只读核对成功后仍须显式结束，刷新可售状态不能绕过。确认写入与后续读取失败分开反馈。
- 全选失败自动只读核对实际勾选；访客批次保持原编号，不在此自动补发。读取失败标记旧数据、隐藏价格合计并关闭修改和结算，显式刷新可恢复。
- 数量草稿复用共享输入保护，包含刷新、返回、退出及窄屏键盘；写入忙态不能先退出。空闲只读加载不拦普通导航。请求失败保留输入，换号不继承。
- 付款卡片按会员/订单隔离，旧结果禁付；不可恢复参数/身份错误暂停轮询，网络及 503 自动恢复，业务未知仍保留库存锁定。终态停止查询，不增加直接标记付款或库存的接口。

原确认、提交、表单、通知、取消和查询接口不变，不改结算 Session Storage。未知加购与数量正文仅留当前标签页内存，不承诺跨硬刷新、关闭或重新登录的持久幂等；这些情况下仍须先人工核对服务端结果。
