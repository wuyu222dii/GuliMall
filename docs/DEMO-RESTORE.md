# Demo 冷备份完整隔离恢复

此入口恢复一份本地模拟 Demo 冷备份，并在恢复副本中继续真实订单、库存与消息处理。付款仍为 LOCAL_TEST，无真实资金；不接第三方或公网。只读核对继续使用 `backup-audit.ps1`，独立 `_test` 演练继续使用 `test.ps1 -Suite Recovery`，两者保护不变。

## 执行前

1. 先完成本机工具、配置和产物预检，构建当前十个服务及前端生产文件，安装锁定的 Chromium。此恢复入口复用当前构建产物，不替代阶段 18 的干净构建验收。
2. 确认常驻模拟环境健康，停止人工操作及其他验收任务。恢复采用顺序切换，会暂停原五项基础设施、十个服务、静态入口和模拟网关。
3. 保存经过校验的 Demo 冷备份及其**原匹配签名配置**。密钥不在数据备份中，不可丢失或重新生成；配置、会员数据、台账和恢复证据保留在私有忽略目录。
4. 暂存已审查的源码变更或使用干净提交。入口导出 Git 索引，不包含未暂存修改；不复制原 `.env` 或演示账号文件到恢复副本。

```powershell
./scripts/simulation.ps1 Diagnose
./scripts/backup.ps1 -Environment Demo -Destination .data/backups/my-demo-cold-copy
./scripts/demo-restore.ps1 `
  -Backup .data/backups/my-demo-cold-copy `
  -PaymentConfig .tools/simulation/payment-config.json
```

参数必须指向实际备份及匹配密钥，目录不能并行使用。错误 manifest、文件路径或哈希、Test 备份和错密钥在暂停原环境前拒绝。现有 Test 入口仍拒绝 Demo；新入口也拒绝 Test 模式。

## 隔离及恢复过程

- 在 `.tools/demo restore <编号>/source` 导出副本，生成新的依赖密码、内部令牌及仅用于副本的管理员。使用随机 `gulimall-handoff-<编号>` 项目，继承现有工作区归属保护，不增加第二套服务管理器。
- 原环境完全停止后，才复用固定本机端口。恢复副本拥有全新 MySQL、Redis、Nacos、ES、RabbitMQ 容器、六个卷和独立网络。上传目录、支付台账与配置也只在副本中；不挂载原数据卷，不加载原 Nacos 配置。SQL 导入空卷且 MySQL 事件调度关闭。
- 启动业务前核对原五个容器均停止、新容器/挂载/凭据归属及端口绑定。拒绝远程或 Spring/Java 隐式覆盖。发现未知业务端口占用明确失败，不结束未知进程。
- 恢复 SQL、Redis RDB、图片和持久支付台账，使用原匹配签名密钥。只在复制的配置/台账中将回调和返回地址绑定到恢复入口，差异记录于 `callback-rebind.json`；金额、支付状态、交易号与密钥不更换。
- 业务启动前保存原订单、库存明细、金额及台账快照；Redis 的原 TTL 自然生效，不复活过期 Session。业务启动后按真实当前时间补偿，不修改期限。
- 在恢复环境读取原订单与本地图片、重建搜索，新建独立商品和会员，经页面完成一笔模拟付款、发货及收货。随后停止副本 RabbitMQ，经页面取消另一笔订单，确认保留“已关闭、库存尚未释放”的持久事件。
- 暂停副本业务/模拟网关，保存新的 SQL/Redis/图片/支付台账冷检查点，销毁本次全部容器与卷，再从该检查点导入全新资源。转储与导入显式使用 utf8mb4；业务启动前重导出整份 SQL，比对冷检查点 SHA256，拒绝中文或时间等数据变化。空 broker 启动后由 SQL 事件补发释放；重复投递扣减与释放消息，核对 ACK、工作单及库存只变化一次。
- 再登录恢复会员，经页面完成另一笔完整交易，核对原交易保留、补偿完成以及新交易可继续。

## 证据及退出

运行目录保存 `result.json`、两代容器编号、`original-before.sql` / `original-after.sql`、两轮浏览器日志及 `original-restored-health.json`。副本 `.tools` 内包含 `original-state.json`、`checkpoint-state.json`、`restore-fixture.json`、`compensation-result.json` 和 `restore-result.json`。浏览器截图在 `output/playwright/demo-restore-*`；失败 trace 沿用动作时序脱敏，清理原始 DOM/网络/输入值。

退出时先停止副本服务和通知重试，再按本次资源归属清理容器/卷，保留私有证据与冷检查点。原环境业务恢复前比较原 SQL 冷转储、`.env`、签名配置和台账哈希，随后启动原常驻模式并执行完整健康诊断。失败也走相同清理和恢复流程；不要在演练未退出时手动启动原服务。

如果操作被进程强制终止，先查看运行目录的项目和 source，确认 Docker 标签、工作区及进程归属后停止该副本；不要按端口盲目结束进程。仅在副本服务、网关及容器停止后，回原目录执行 `simulation.ps1 Start` 和 `Diagnose`。`result.json` 中通过、资源清理和原模式恢复三项都必须成立才算演练成功。

## 验收范围

本轮针对当前本机冷备份和单进程模拟网关。原备份有待处理交易时，恢复后允许按当前时间合法补偿，并按库存工作单变化核对；原环境本身始终暂停。原备份只有终态交易时，待补偿证据由恢复副本通过真实业务生成，不改原库造状态。

此入口不是原目录原地恢复、在线热备、双环境并行平台或生产灾备工具。独立机器/第二人、真实平台、公网、实体设备、高可用和容量仍须另验。
