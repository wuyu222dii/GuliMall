## 1. 准备、启动与诊断

阶段 18 的工具准备、结构化预检、Git 干净导出及本机隔离运行步骤见 [HANDOFF-SETUP.md](HANDOFF-SETUP.md)。独立机器与第二位操作者验收仍待补。

1. 首次机器准备按 [开发说明](DEVELOPMENT.md) 配置 JDK 8、Maven、Node/npm 与 Docker Desktop Linux 引擎，完成 setup 和构建；已有库禁止重跑初始化或删卷。
2. 管理员账号与 BCrypt 摘要在 .env，明文密码由环境所有者私下保管；忘记时使用已提供的交互工具生成新摘要，不能从摘要反推密码。不要使用测试环境配置替换 .env。
3. 启动 `./scripts/simulation.ps1 Start`，访问 http://127.0.0.1:8080；后台 `/admin`。执行 Status 或 Diagnose，全部就绪再演示。`Diagnose -Json` 提供结构化结果，失败退出 1，输出的恢复命令需操作者按原因执行。
4. Stop 保留数据、图片和台账；基础设施可继续运行。另执行 dev.ps1 Down 可停容器并保留卷。当前入口不会注册开机任务或 Windows 服务。

基础资料维护可先按名称/编号查找，品牌、分组、属性使用已有状态/分类/类型条件；保存后按编号定位，删除后核对结果。出现旧数据或未知结果提示时先重新加载，不直接重复新增或删除。

编辑后取消、切换或离开时，可先选择“继续编辑”；确认放弃不会重发业务请求，未知结果仍需核对。顶部“全部分类”可展开完整层级，商品详情使用“加购并前往购物车”，随后仍需选择商品并提交订单。

## 2. 一笔成功交易

- [ ] 管理员在商品管理点击“新建商品”，填入双 SKU 示例，使用独立名称；可设单价 0.10 / 3.45。
- [ ] 上传 PNG/JPEG，给两个 SKU 选择实际上传图片和主图，保存并记录 SPU/SKU 编号。
- [ ] 在采购与库存分别建需求，选仓库、数量与预计采购总金额；保存绑定原编号，下一 SKU 使用“新建下一条需求”；合并、领取、完成并核对可用库存。
- [ ] 商品上架，确认同步成功。搜索时使用有区分度的词；中英文编号建议用空格分隔，共同中文前缀会匹配多件商品。
- [ ] 退出管理员，注册会员。页面明确显示开发验证码；保存地址，搜索并将两种 SKU 加购，修改数量和勾选。
- [ ] 红色 3 件与蓝色 1 件应付 3.75，提交后记录订单号。超时先查询原提交，不自动开始第二笔订单。
- [ ] 打开模拟付款，核对“无真实资金”提示并确认付款；返回后等待付款和库存扣减均确认。
- [ ] 管理员可按完整订单号/状态查询，URL 保留页码；点击“详情 / 物流”进入独立详情核对处理进度，“返回订单查询”恢复条件；填写物流并发货。运单号仅字母、数字和连字符，不能含下划线。
- [ ] 会员查看物流，收到模拟包裹后确认收货；刷新仍为已完成，历史与金额保留。

库存处理未知或未确认时，不直接改数据库，也不能发货。交易完成后再次购买，在结算页明确点击“开始下一次确认”。建议使用专用演示商品，保留各次编号，便于核对。

## 3. 失败与补偿演示

- 新建一笔待付款订单，打开模拟付款选“模拟付款失败”或“返回订单（不付款）”，返回仍为待付款，可以重试。
- 在我的订单取消并确认，等待显示关闭且库存释放。若为关闭确认中，保留原订单，恢复依赖后查询；不能把网络超时当成取消成功。
- 在隔离环境运行 `./scripts/test.ps1 -Suite Failure`，演示支付查询失败、订单重启及 broker 中断后的持久事件恢复。不要为演示故障随意停止正在人工操作的环境。
- Diagnose 提示具体服务故障时查看对应日志，恢复后查询原结果；订单进度可见发布确认、消费确认、库存结果、重试及到期检查。状态 9 需人工核对，不自动退款或发货。

## 5. 备份、审计与恢复

```powershell
./scripts/backup.ps1 -Environment Demo
# 替换为上一步输出的实际目录：
./scripts/backup-audit.ps1 -Backup '.data/backups/本次目录'
# 在维护窗口完整恢复 Demo 副本，必须提供原匹配密钥：
./scripts/demo-restore.ps1 -Backup '.data/backups/本次目录' -PaymentConfig '.tools/simulation/payment-config.json'
```

冷备份同时暂停业务及模拟网关，保存 SQL、Redis、图片与 payment-ledger.json，完成后恢复原模式。模拟签名配置 `.tools/simulation/payment-config.json` 和 .env 单独私下保管；没有原匹配密钥，不能用重新生成密钥绕过台账指纹。

审计在新实例只读核对同一交易、库存、金额、图片和 Redis，不启动补偿，不切换当前配置。[完整恢复入口](DEMO-RESTORE.md) 则暂停原环境，在独立副本启动业务并验证补偿、继续交易，结束清理本次资源并恢复原模式。状态 8/9 仍按既有规则处理，不直接改库。不要向当前库导入 dump。

本机已完成命令与浏览器步骤核对；尚未由第二位操作者在全新机器独立演练。真实支付宝、短信、OSS、公网回调、实体手机、多浏览器、容量和高可用不在本轮验收范围。

## 阶段 32–35 操作核对

- 新增采购需求出现结果未知时，查询原创建结果或重试原请求；不要清空记录再创建。查回原编号后继续更新或合并。删除后原请求只报告已删除，不恢复。
- 采购完成先选择失败项并填写原因，再尝试切单、刷新或退出；取消确认应保留输入。商品保存/上传中等待结果，不通过离开确认清除未知提交。
- 采购、仓库、基础资料查询后复制 URL，刷新或重新登录应恢复条件；选择器内部关键词不在本轮 URL 范围。同步记录按 SPU/状态定位，返回商品保留原筛选。
- 自然 Session 补验使用独立 Test 套件实际闲置两小时；人工演示不要并行进入测试入口。恢复演练须持有原匹配密钥，全部在隔离副本进行。
