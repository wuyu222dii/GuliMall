## 复现及实现

两浏览器先复现：地址翻页不改变 URL；在第二页新增后找不到刚创建的地址；`?page=2` 刷新会回到本地第一页；仓库被当前筛选排除且保存后回到空的新建表单。真实 Test 请求的复现结果在 `.tools/stage37-repro-{chromium,edge}.json`。

- 地址明确保存返回编号，列表读取失败仍能按原编号只读查询、显式进入编辑。新增和设默认回第一页，普通编辑保持页码；未保存输入先确认，未知原输入继续冻结，不由查询覆盖。正文与写入结果仅保留当前页面内存，不自动持久化个人信息。
- 仓库保存后表单绑定原编号，继续保存走更新；列表失败不变回新建。筛选或分页未包含记录时给出说明，可只读查看，也可显式按编号替换筛选。无筛选的新增利用真实分页总数定位末页，不扫描全量页面猜位置。仓库详情不存在返回 404，非法编号 400；不改库存或采购引用。
- 新写入开始时清除旧确认卡片，防止后续未知请求显示上一条“已保存”。详情读取仅更新发起时的那次结果；写入完成后，较早读取的迟到响应不会覆盖新结果。
- 地址页码进入 URL，支持刷新、复制、前进/返回和严格站内登录回跳。会员订单及搜索的合法越界页码用替换历史纠正，不把越界解释为没有记录。
- 消费者标量白名单、枚举、编号、重复及未知参数均有明确错误和清除入口；对应 API 拒绝非法参数。保留分类别名、多品牌及多规格协议，不把数组折叠为单值。不增加规格聚合面板。

回归发现仓库子表单在普通 effect 中通知父页脏状态存在时间窗口：刚输入就按浏览器返回时会丢输入。改为布局阶段同步通知及清理，在两个浏览器中保留快速返回断言，不通过增加等待时间规避。

完整回归还复现新增后的末页定位与立即查询相互覆盖：分页变化会重置查询输入。查询输入现在只随已确认 URL 关键词变化而更新；用户已经输入新查询时，后台定位不再覆盖上下文。原仓库用例增加真实列表响应延迟，输入新编号后才放行，明确检查输入与第一页均保留，再正常提交查询，不通过等待自动定位结束绕过竞态。

## 查询与接口约定

| 入口 | 可用参数及说明 |
|---|---|
| `/member/address` | 仅 `page`，1–1000000；默认 1 |
| `/member/orders` 及现有详情返回查询 | `page/status/orderSn`，状态 0–9，订单号完整 32 位小写十六进制 |
| `/search` | `page/keyword/catalogId/catalog3Id/brandId/attrs/min/max/hasStock/sort`；UI 每页 12、ES 窗口最多前 10000 项，对应页码最多 833 |
| 搜索多值 | `brandId` 可重复，兼容逗号分隔，最多 20；`attrs` 可重复，单项为 `属性编号_值`，最多 20；值内逗号作为正文保留 |
| 分类别名 | `catalogId` 与 `catalog3Id` 可用，同现时必须一致；0 表示不限定分类 |
| 价格、库存、排序 | 价格普通十进制、最多 12 位整数及 2 位小数；库存 0/1；排序 default/price_asc/price_desc |
| 地址与订单列表 API | 另外允许 `limit`（1–100），不接受客户端 memberId、任意排序、未知或重复标量；归属仍取 Session |
| 仓库查询 | 复用既有 `/api/admin/ware/wareinfo/list`、`info/{id}`、save/update；查询 URL 沿用采购页 `tab=warehouses&page&key` |

所有接口继续沿用 R/PageUtils、Session、CSRF 与管理员保护。旧验收中“伪造 memberId 被忽略”更新为“未知参数明确 400”，同时保留正常当前会员列表、跨会员 403 和金额/地址快照断言，不减少安全检查。
