# 真实下单与库存锁定（阶段 6）

沿用 Java 8 / Spring Boot 2.1.8、共享 Redis Session 和现有业务分层。复用订单、明细、操作历史和库存工作单；订单库新增提交记录。订单和库存各自使用本地事务，通过订单号幂等接口和持久化状态恢复，不引入 Seata。

## 页面与浏览器接口

全部经 `/api`，会员身份从 Session 获取，写操作检查 CSRF。`X-Cart-Owner` 只检测标签页账号错位，不能指定操作其他会员。

| 方法与路径 | 行为 |
|---|---|
| POST `/api/order/mine/confirm` | 读取本人已选购物车、当前商品/价格/库存与地址；保存 15 分钟确认令牌及商品选择快照 |
| POST `/api/order/mine/submit` | 仅接受 `{token,addressId}`；服务端校验归属、重新算价、持久化创建请求并尝试锁库 |
| GET `/api/order/mine/submissions/{token}` | 查询本人原提交结果；未创建时返回原确认单，不新建令牌 |
| POST `/api/order/mine/submissions/{token}/retire` | 与提交竞争同一行锁：未消费则使其失效；已消费则返回原订单，不能撤回或另建同一请求 |
| GET `/api/order/mine` | 当前会员订单，按创建 ID 降序分页 |
| GET `/api/order/mine/{id}` | 本人订单与明细 |
| GET `/api/order/mine/by-number/{sn}` | 按订单号查询本人订单与明细 |

`/checkout` 显示真实确认商品和本人地址，提交按钮创建实际订单。点击前在按会员隔离的 sessionStorage 保存原令牌与地址编号，不保存地址内容。请求超时、刷新、服务重启后先查询原结果，再重试原令牌；更换未提交确认单前由服务端原子使旧令牌失效。已创建订单只能查询原结果。明确开始另一笔确认需点击“Start a new confirmation”，不会因刷新自动再下单。

`/member/orders` 可刷新列表、展开订单商品和地址快照，明确显示创建中/关闭确认中。管理员保留只读订单列表。付款接口尚未接入本阶段交易链，不生成支付表单；支付、自动关单和发货属于后续阶段。

## 令牌、金额与数据边界

令牌存在 `oms_order_submit`，以 UUID 为主键、会员为所有者，订单号有唯一约束。提交事务 `SELECT ... FOR UPDATE` 检查未过期且未消费，并将令牌绑定、订单及全部明细一次提交。重复请求读取同一订单；消费后重试不受原 15 分钟到期影响，不能改用另一个地址。这样没有“Redis 已消费但订单库尚未提交”的间隙，Redis/进程故障也不会丢失已落库请求。

确认单固定本次勾选的 SKU、数量和购物车版本。提交读取商品最新资料，检查仍上架且单价与确认单一致；变价、下架或删除要求重新确认。最终锁库才是所需数量是否充足的权威判断，提交前的商品元数据查询不依赖仓储可用性。客户端 memberId、items、price、payAmount、运费或优惠字段不参与可信计算。

地址由会员服务按当前 Session 会员 ID 与地址 ID 双重校验，不接受客户端地址文本。订单保存收货人、电话和地址快照；之后改地址不改订单。明细保存 SKU、SPU、分类、名称、图片、销售属性、数量、单价及行金额。全部合计使用 BigDecimal，运费和优惠为 0，每 SKU 1–999 件、最多 100 种，金额不超过现有 DECIMAL(20,2)。

消费者无法读取其他会员的确认令牌、订单和明细。库存锁定、释放、购物车订单清理及内部地址接口受内部令牌保护，不配置浏览器路由。旧订单/库存工作单的直接保存、修改和删除接口拒绝绕过业务状态流转。

## 状态与恢复

| 订单状态 | 含义与恢复 |
|---|---|
| 6 创建中 | 订单/明细及请求已落库；查询库存工作单，再按原订单号尝试锁定 |
| 0 待付款 | 已确认工作单 LOCKED；设置 30 分钟付款截止时间，才允许清理本次购物车 |
| 7 关闭确认中 | 创建失败或超过 5 分钟创建期限；持久化关闭意图后等待库存释放确认 |
| 4 已关闭 | 库存服务已经确认 RELEASED，不再把未知结果当成失败 |

库存工作单以订单号唯一，明细 `(task_id,sku_id)` 唯一。锁定在一个库存本地事务内执行：同订单并发请求串行检查相同规范化 SKU/数量；SKU 按编号顺序尝试仓库，`UPDATE ... WHERE stock-stock_locked >= quantity` 原子增加锁定数。任一 SKU 无法满足则整笔库存事务回滚。每 SKU 只选一个足量仓库，不拆分跨仓。

工作单状态 1=LOCKED、2=RELEASED；明细状态 1=锁定、2=释放。释放先按订单号创建/锁住工作单，即使锁库尚未到达，也留下 RELEASED 记录。迟到的锁库请求看到该记录只能返回 RELEASED。已有锁定的减少与工作单/明细更新在同一事务内，重复释放不再减库存。

锁库响应超时、连接失败或订单进程崩溃均保留创建中，不能直接清空购物车或认为没有锁到库存。每轮恢复执行后间隔 10 秒再次扫描，每批最多 20 笔；读取库存真实工作单后继续待付款，或持久化关闭意图并幂等释放。创建期限到达时必须确认释放后才转已关闭；释放结果未知时继续保留关闭确认中。

订单、明细、令牌、工作单和恢复时间均在 MySQL 中。只要这些记录和 Redis 持久化卷保留，重启后可继续；没有靠进程内队列保存必须执行的动作。库存数据被人工修改为不一致时拒绝盲目释放，需人工检查。查询结果和操作历史可追踪状态。

**阶段边界：30 分钟付款截止时间已保存，但待付款超时关闭、MQ/持久化事件、支付验签及实际扣减库存在阶段 7。当前待付款订单会保留锁定，不能当作生产交易系统使用。**

## 购物车清理

购物车增加/改量/勾选/合并会更新条目版本。只有确认待付款后，订单服务才使用落库明细版本请求 Redis Lua 清理，并写入按订单号的去重凭据。仅移除版本仍匹配的条目；会员之后改量、取消再勾选、删除再加购或新增商品均不被旧请求误删。即使数量改回原值，版本仍不同。

购物车服务不可用时，已成功锁定的订单继续为待付款，`cart_cleaned=0` 由恢复任务重试。失败/创建中/关闭确认中的订单保留购物车。订单清理凭据不随购物车清空删除，避免迟到重试删除新加商品；其备份与生命周期边界同 Redis 购物车合并记录。改过的条目选择保留整项，不自动猜测用户的新购买意图。

## 迁移、构建与运行验收

空卷使用更新后的 `infra/mysql/001-schema.sql`，共 70 张表。已有卷先备份订单库/库存库，再运行一次 `infra/migrations/004-order-creation.sql`；脚本在 DDL 前检查重复订单号、工作单和 SKU 明细，不删除或合并既有数据。当前机器已执行，迁移前私有备份在 `.tools/stage6-before.sql`。

```powershell
# 已有演示库，完成备份并确认本阶段尚未迁移后执行一次：
./scripts/services.ps1 Stop
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysqldump -ugulimall --no-tablespaces --single-transaction --databases gulimall_oms_demo gulimall_wms_demo' |
  Set-Content .tools/order-stock-before.sql -Encoding utf8
# 上一步必须成功并确认备份文件非空，再继续：
Get-Content infra/migrations/004-order-creation.sql -Raw |
  docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql -ugulimall'
mvn -B clean install
./scripts/services.ps1 Start
./scripts/dev.ps1 Smoke
cd gulimall-web
npm run lint
npm run build
```

默认单元检查不连业务库。真实运行验收使用本机独立 `_demo` 库，创建专用双会员、地址、商品和仓库；测试结束释放/清理自己的锁定、订单、工作单、购物车及索引，保留演示会员与种子库存。不得与其他故障验收或人工演示并发运行。

```powershell
$env:GULIMALL_ACCEPTANCE='1'
$env:GULIMALL_FAULTS='1'
node --test scripts/order.acceptance.mjs
```

验收覆盖 20 路重复提交、双会员争最后一件、多商品回滚、单 SKU 不跨仓、确认令牌到期/失效、价格与地址快照、购物车版本保护，以及仓储/购物车不可用、响应丢失、锁库后杀订单进程、创建超时期间释放未知与恢复。为避免等待 15/5 分钟，仅修改自己测试令牌/订单的到期字段来加速期限场景。

故障脚本用 Node 标准库本地 HTTP 代理，先将锁库送达并确认提交，再丢弃响应或终止订单 JVM。仅被重启的测试订单进程临时继承 `ORDER_STOCK_URL` 指向代理，默认留空仍走 Nacos；finally 恢复默认订单进程。此变量不写入 .env，不是浏览器参数。服务以 `scripts/services.ps1` 管理，限独立本机演示环境。

尚未进行实体手机、多浏览器、集群或负载压测。单实例恢复扫描与单仓满足 SKU 是当前演示边界；大规模吞吐和事件驱动处理在有实际需求及回归保护后另行扩展。
