## 五类表单的输入保护

地址、商品基础资料、仓库、采购需求和发货物流按可编辑字段与进入编辑时的基线比较，不把编号、查询条件或普通数字输入的类型差异算成修改。未修改的表单可以直接切换和离开；只要输入有变化，站内导航、切换对象和取消编辑均先显示统一确认，可继续编辑或明确放弃后继续。仓库与采购需求共享一个页面级导航拦截，子表单只报告自身修改/提交状态，不叠加 Router blocker。

确认框支持键盘焦点、Tab/Shift+Tab 循环及 Escape 返回，沿用原有按钮与配色。刷新/关闭共用 beforeunload 原生提醒；退出登录先询问，再按原流程销毁会话，选择继续编辑不会先退出。有修改的提交处理中，确认框不允许提前丢弃输入；已保存后的只读刷新不阻止离开。来自其他标签页的退出、会话失效等安全边界仍以服务端身份为准，不尝试阻止身份失效。

确认保存后更新或清空对应基线；保存已确认但列表刷新失败，不误报该次输入未保存。失败时输入保留。发货响应丢失时继续保留物流；重新查询若确认同一物流已发货/完成，再解除修改标记，仍由原服务端履约门禁拒绝非法发货。

提醒本身不发送业务写入、不重发请求、不调用 storage 清理，不创建自动草稿，也不将地址、密码或验证码保存到浏览器持久存储。商品创建快照、采购原请求和结算令牌继续沿用原逻辑。已有“已核对，放弃”及“人工结束记录”仍是操作者明确核对后的独立流程；普通取消与导航不能替代它们。
