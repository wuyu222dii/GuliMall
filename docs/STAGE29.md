# 阶段 29：基础资料查询、分页与保存删除定位

基线 74163ea，在 codex/stage29 实施。继续 Java 8、Boot 2.1.8、单管理员、开发验证码、本地图片和 LOCAL_TEST 持久模拟支付；不接真实第三方或公网。本阶段没有后端业务、表结构、迁移、库存/支付状态机或期限变更。

## 查询与分页

复用 GET /api/admin/product/admin/catalog 的完整 metadata，在页面内按类型查询、每页 20 条。名称忽略大小写并去除查询首尾空格，编号精确匹配，也保留名称包含数字的查找。品牌可筛启用/隐藏；分组按所属三级分类筛选；属性可组合分类、启用/停用和基础/销售类型。分组没有独立启用字段，不虚构状态。

分类保留完整树的数据关系，按同级 sort、编号稳定排序并深度优先展示，显示完整层级路径、层级和父分类编号；可以查名称或编号定位。品牌、分组和属性按编号升序稳定分页。清除条件及切换类型回到第一页；翻页不重新读取后端或改动业务数据。

筛选与分页仅作用于表格，编辑表单继续使用完整分类、分组及关系集合，不把切片数据写回覆盖全集。没有引入数据表库、通用表格或新 API。metadata 仍全量返回，大数据量时的后端分页优化继续后置，不据本机验收声称容量通过。

## 操作结果与定位

- 保存收到确认后绑定原编号；刷新成功按编号定位所在页并标明“当前定位”。记录仍匹配原筛选时保留条件；不匹配时明确说明已清除条件再定位，避免保存成功却找不到记录。
- 保存已确认但刷新失败，仍显示已保存、保留原编号和输入，旧列表标为旧数据并暂停修改。重新加载成功后继续定位，不另建同名记录。
- 删除只发送原类型与编号，保留后端子分类、商品、分组关联及属性引用保护。成功后保留筛选，末页为空时退到有效页；只在删除当前编辑对象时取消其编辑。
- 删除已确认、列表刷新失败分别提示，保留筛选和旧数据标识，重新加载前暂停修改。删除响应丢失时不提示成功、不自动重发；加载完整资料后定位原编号或明确说明未找到，交由操作者核对。
- 保存、删除共用即时提交锁，连点不产生多个并发请求。业务拒绝和接口失败保留输入；查询、分页不会绕过 Session、CSRF 或引用删除检查。

普通表单切换的未保存提醒仍属于阶段 30；本阶段不增加自动草稿或跨标签页资料创建防重。
