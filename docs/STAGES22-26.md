## 阶段 22

会员地址写入锁定 `ums_member` 中的当前会员行，再保存地址和整理默认标记；空地址集也受同一行锁保护。最多保留一个默认地址，不自动把非默认地址设为默认。历史多个默认地址只读报告，首次修改时优先本次指定地址，否则保留剩余原默认中最小编号；不会删除其他地址。删除默认后可以没有默认地址。旧管理地址 CRUD 写接口拒绝旁路写入，会员页面及内部订单读取地址接口保持兼容。

`PUT /api/member/addresses/{id}/default` 校验 Session、CSRF 和归属。列表按默认优先、编号倒序分页，增加只读 `multipleDefaults` 提示。编辑沿用 PUT，新增忽略客户端会员与地址编号。前端使用即时提交锁防连点；新增结果未知时保留表单、阻止再次创建，要求先刷新核对并显式放弃表单。新增没有服务端请求幂等承诺。

运行测试仅写独立 `_test` 数据库，人工演示地址不修改。旧默认不一致夹具只在通过测试库校验后注入。订单地址继续使用创建时快照。

本轮原环境恢复健康后，冷备份保存于私有 `.data/backups/round6-before`。原交易、库存、图片、密钥、配置及支付台账指纹保存于 `.tools/round6-original-state.json`，不提交私有数据。各阶段日志使用 `.tools/stage22-*` 等独立前缀；通过后填写实际结果，不将失败或跳过计为通过。

阶段 22 结果：member 及依赖构建成功，Java 2 通过/1 旧类忽略；前端 lint/build 通过；Auth 9 个业务场景（原 8 + 新增 1）通过；Browser 6 项（Chromium/Edge 各含地址专项）通过。结算无唯一默认时必须手选；未提交的已选地址删除后不继续沿用。375px 地址截图已查看。最终 18 项诊断健康，原交易/库存/图片/配置/密钥/台账指纹相同。证据索引 `.tools/stage22-final/manifest.json`。

## 阶段 23

保存接口可选 creationRequestId，创建时使用 UUID；不带标识的旧调用继续兼容。现有 SPU 表增加可空 creation_request_id / creation_request_hash 和唯一索引，不新增表。业务事务内保存 SPU、SKU 与标识；唯一冲突的输家先完整回滚，再查询赢家。相同请求和摘要返回原商品，不覆盖之后的编辑；不同摘要 409。GET /api/admin/product/spuinfo/creation/{requestId} 只给管理员返回 found/id，不返回摘要。摘要固定白名单、对象排序、数字规范化并保留数组顺序，忽略未启用营销字段与客户端属性名称。

新页面在 Session Storage 保留原提交快照，未知期间锁定输入并提供查询/原请求重试；明确 400 校验失败可修改后重提。离开确认使用现有 React Router 的数据路由与 useBlocker，覆盖站内导航/返回，并使用 beforeunload 提醒关闭或刷新。浏览器存储损坏明确拒绝新建，不静默重生成请求。

迁移 infra/migrations/006-product-creation.sql 先在独立 Test 执行两次并比较旧字段，再在冷备份后的 Demo 执行，全部旧商品字段一致。空库建表同步更新；迁移在添加唯一约束前检查重复值。既有数据库升级须先冷备份，再在目标 MySQL 执行此迁移，不重跑初始化。Test 入口在启动服务前自动执行同一迁移。旧备份恢复时的迁移接入与兼容验收安排在阶段 26，当前不能把旧备份直接作为新界面的恢复证据。
