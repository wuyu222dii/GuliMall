## 40：地址和仓库创建持久防重

- 地址仍物理删除；新增最小专用回执表，保存会员、请求 UUID、原摘要、原地址编号，按会员/请求唯一，不保存地址正文，不级联删除回执。复用会员行锁，将创建、默认处理及回执置于同一事务。
- 仓库现有表增加可空请求号/摘要与唯一索引，历史标识为空，不改库存及采购引用。
- 同号同内容返回原编号，不覆盖编辑内容、不重复切默认；不同内容 409；已删除地址查询为 found/deleted，重放 409，不复活。竞争失败事务完整回滚后再读胜出结果。
- 原 POST/save 增可选 creationRequestId。新增当前会员 addresses/creation/{requestId} 与管理员仓库 creation 查询；返回 found/id/deleted，不返回摘要或正文。
- 前端先保存稳定请求号及身份绑定指纹，未知时查询或重试原请求，不自动换号。地址正文不自动持久化；刷新未命中需重新输入匹配原指纹的内容才能同号重试。旧无标识请求仍人工核对。
- 新迁移先验证 Test，再冷备份 Demo。接齐空库、迁移检查、测试启动及全部恢复入口，明确兼容 71 表旧结构与迁移后 72 表，不简单放宽表数保护。

验收：并发、丢响应、刷新/重登/重启不重复；失败无孤立业务行或回执；编辑后不覆盖、删除后不复活；默认唯一、订单地址快照和仓库引用不变。

## 41：会员增量加购持久防重

原 POST 增可选 requestId，新前端始终携带；旧调用保留增量语义。新增当前会员 GET /api/cart/items/requests/{requestId} 查询执行结果及原 SKU/数量。

加购回执与 items 同会员哈希槽，用一次 Redis Lua 原子更新数量、revision 和回执。摘要仅含 SKU/增量数量。成功重放先于实时商品校验返回，不增量、不改变 revision；首次请求仍检查可售性。同号异内容 409。clear/remove/ordered 不删除回执，旧请求不加回商品。

回执无 TTL、不淘汰，每会员最多 10000 条；满时拒绝新请求，旧回执仍可查询重放。浏览器按会员保留请求号/SKU/数量，刷新只读查询，显式重试同号。验收覆盖并发、丢响应、Redis 重启、清空/删除/下单重放、后续新 revision 不被旧订单清理，以及原访客合并和会员隔离。

## 统一规则

请求号为小写 UUID，非法400、冲突409；归属由 Session 确定、写请求保留 CSRF，不能泄露其他会员回执。旧记录不猜造标识。生命周期串行、等待真实就绪，不清库或删历史任务来缩短等待；失败也恢复原模式。

本轮不做四类资料新增持久防重、通用幂等/监控框架、会员账号、退款、营销、角色权限或真实服务。独立机器/第二操作者/实体手机/其他内核/辅助技术/容量与高可用仍待补验。
