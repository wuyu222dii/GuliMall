## 四、下一轮建议：阶段 36–39

本节是**待批准的实施建议**，不是已获授权的代码改动。本轮建议只有两个核心目标：普通表单未知结果可正确核对；消费者查询及交易异常有明确恢复路径。

| 阶段 | 核心交付 | 估算投入 | 前置 |
|---|---|---:|---|
| 36 | 普通表单未知结果和写入忙态保护 | 8–14 小时 | 恢复模拟环境，独立 Test 先复现 |
| 37 | 保存结果定位、消费者查询/分页恢复 | 12–20 小时 | 36 |
| 38 | 加购/购物车和付款失败恢复收口 | 8–14 小时 | 37 |
| 39 | 定向测试、全量回归、恢复兼容与交付 | 12–20 小时 | 36–38 |

合计 **40–68 小时**，加约 20% 缓冲为 **48–82 小时**。沿用每周 8 小时的规划假设约 **6–11 周**。这是估算，包含实现、针对性测试和联调，不是交付承诺；服务启动、队列处理等墙钟等待另记。阶段 36 完成后按实际问题数量校准。每阶段拆成 2–4 小时任务，验收后独立提交。

### 阶段 36：先处理普通表单未知与忙态

1. **环境及复现（2–4 小时）**：检查 Git、产物、端口归属和私有配置；恢复 Docker/LOCAL_TEST，18 项诊断通过后进入 Test。保留已有库和图片，不初始化。分别复现地址创建成功但响应被丢弃后修改输入/刷新，以及干净品牌表单上传期间切换、离开、退出和浏览器刷新。
2. **未知结果一致性（2–4 小时）**：未知时保留并冻结原提交内容、暂停新增重发，提供刷新核对与明确结束入口。地址正文只保留内存，不自动存入 localStorage/Session Storage；若增加跨刷新提示，仅保存按身份隔离的不含正文的待核对标记，不能用标记冒充服务端创建结果。
3. **写入忙态（2–4 小时）**：只对实际复现问题调整共享保护；保存/上传未结束时不先退出 Session 或切上下文，保留取消离开和原生关闭提醒。普通只读查询和干净表单不误拦。
4. **专项验收（2–4 小时，可与前项合并）**：Chromium/Edge、375px/键盘、校验失败可修正、未知不可改原请求、明确结束后可开始新记录；换号不显示前一身份待核对信息。

不新增表、持久字段或通用幂等框架，不把普通表单提升为“刷新后精确查回同一创建”的保证。仓库和资料已冻结未知输入，优先复用并验证，不重复实现。

### 阶段 37：结果可找到，查询可恢复

1. **保留保存编号（2–4 小时）**：地址、仓库明确展示已确认保存的编号；后续列表读取失败时仍保留结果核对入口，不把已保存记录重新当作新建。
2. **定位与现有筛选协调（2–4 小时）**：地址新增/设默认后回到合理列表页；编辑保留当前上下文；仓库被现有条件排除时明确说明并提供显式清除筛选/查看记录入口，不静默清条件，不循环拉全量页面猜位置。复用已有详情读取及分页，不直接改库存或历史地址快照。
3. **消费者 URL（2–4 小时）**：地址页码进入 URL，配套安全登录回跳；会员订单、搜索的越界页以替换历史纠正，只有实际无数据才显示空状态。
4. **参数约定（2–4 小时）**：明确标量白名单、枚举、编号、重复参数与清除入口；前后端对应校验，错误 400。保留现有分类别名兼容；合法的多值 `brandId/attrs` 按协议保留，不能直接照搬后台“所有参数只出现一次”或继续折叠成单值。
5. **运行验收（2–4 小时）**：查询、翻页、刷新、前后退、复制地址和重新登录恢复；失败不伪装空结果。地址/订单仍仅当前会员可读，仓库资料维护不改变采购/库存引用。

本阶段不建设完整规格聚合筛选面板，不把消费者返回格式改成尚未接通的旧模板模型。

### 阶段 38：购物与付款的异常可恢复

1. **增量加购未知（2–4 小时）**：先复现服务端加购成功、响应丢失；明确提示先读取购物车核对，不把再次点击当作安全重试，不自动重发增量。保留显式继续购买；不承诺普通加购持久幂等。
2. **购物车局部写入（2–4 小时）**：注入全选第二/第三个 SKU 请求失败，明确可能部分保存；通过只读刷新核对，刷新也失败时保留旧数据并标记状态。保留不可售校验、身份隔离、访客原合并批次和结算门禁。
3. **数量草稿（2–4 小时，可与前项合并）**：未点击更新的数量在导航/退出前明确保留或放弃；刷新本来具有恢复服务端结果的语义，继续显式呈现。草稿不作为结算数量，不跨会员保存。
4. **付款状态恢复（2–4 小时）**：先复现查询失败及 403/404；旧卡片标明非最新状态，恢复查询前不根据旧状态继续付款。明确不可恢复错误暂停自动查询并提供返回/手动重查；503、网络失败和业务未知结果保留恢复查询，不伪造关闭或释放库存。
5. **验收（融入上述任务）**：真实延迟/断连/丢响应、错误会员、不存在订单、服务恢复、已完成/已确认关闭停止轮询，未知结果仍可恢复。保留服务端付款校验、原订单/确认令牌和所有履约门禁。

不改订单/支付/库存状态机、30 分钟期限或 7200 秒 Session 配置；不增加直接标记付款、扣库、释放或退款的模拟接口。

## 五、后置功能与待补验

### 当前不纳入上述工时的新能力

- **普通新增表单持久防重**：地址、仓库、四类资料仍缺。不是简单加一个前端 UUID：地址物理删除、默认统计及订单内部读址需要兼容；分类已有相反语义的逻辑删除值，其他资料还有关联删除保护。若实施需单列持久字段、原摘要、唯一约束、删除后重放及恢复迁移范围，不能隐含在页面反馈中。
- **高级搜索属性面板**：后端支持属性条件，但消费者界面未接通，当前 PageUtils 也未返回完整聚合选项。后续可补规格筛选、多值 URL 和已选条件展示，不是重新建设基本搜索。
- **规模优化**：基础资料仍全量读取后前端分页，搜索库存为定期快照，任务批处理有等待。先在独立 Test 记录数据量、响应字节、加载/筛选时间、同步等待，再决定后端分页或分域选项接口；没有测量依据不新增监控平台或固定完成百分比。
- **新增业务页面**：会员资料、修改/找回密码、售后退款、优惠券/积分/秒杀、角色权限、报表、首页运营、物流轨迹、盘点调拨。没有相应闭环，实体/CRUD 不计完成；需另立业务计划。

### 继续待补验的边界

| 边界 | 当前证据与待办 |
|---|---|
| 独立机器、第二位操作者 | 本机干净目录和隔离副本不替代真实第二台机器/另一位操作者 |
| 实体手机/触摸、Firefox/Safari、辅助技术 | Chromium/Edge、窄视口和键盘不等于跨内核、真实设备或屏幕阅读器验收 |
| 容量、并发负载、高可用、在线热备 | 已有业务并发正确性与本机冷恢复，不是生产负载/灾备承诺 |
| 真实支付宝/公网通知、真实短信、OSS | 本轮全部继续不接、不开放公网；模拟通过不证明平台兼容 |
