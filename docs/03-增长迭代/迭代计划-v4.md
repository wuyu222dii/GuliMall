## 四、各阶段具体任务

### 18：环境可复制与交接准备

1. 使用干净工作目录核对已跟踪文件、构建所需依赖和实际版本；不能依赖当前 Git 忽略目录中的工具、凭据或历史夹具。
2. 复用 setup/dev/simulation，补齐缺失预检及日志说明；缺工具、配置错误、端口冲突明确失败，不结束未知进程、不覆盖配置或初始化已有库。
3. 固定一个 Windows + Docker Desktop 的交接路径：空演示环境初始化、构建、启动、诊断、成功/取消交易、停止重启。私有凭据由接收者自行准备。
4. 另一位操作者在独立机器完成上述步骤并记录阻塞、耗时和版本；没有实际资源时此项保持待补验。

验收：本机干净目录准备结果可复核；独立机器具备自己的数据库卷、私有配置及模拟密钥，能够完成成功交易和取消，并在重启后保留结果。原工作区的数据、配置和进程不受影响。

### 19：目标浏览器与交互边界

1. 复用 Browser 套件和 _test 保护；保留 Chromium 两轮完整链，新增本机 Edge 的登录/恢复会话、搜索加购、下单付款、取消与订单操作，不遍历所有浏览器组合。
2. 补会话失效时重新登录后查询原订单、页面返回/刷新、连续购买和双标签提交的明确场景；服务端原幂等和归属校验继续生效。
3. 桌面与 375px 核对导航、表单、按钮和局部表格滚动，补关键键盘焦点/标签检查；只修实际发现的问题，不重做视觉系统。
4. 复用现有截图与 trace 脱敏、仅本机网络和成功/失败后的原模式恢复。

验收：目标浏览器指定场景通过；无重复订单或库存处理，无跨会员数据；登录过期和网络失败不丢失原提交。Edge 与默认 Chromium 同属 Chromium 系覆盖，不能据此宣称 Firefox/Safari 或实体手机通过。

### 20：Demo 快照完整隔离恢复

1. 保留现有 Test Recovery 硬性校验；设计独立 Demo 恢复入口，先核对 manifest、文件路径/哈希、原匹配签名配置和目标资源归属。禁止导入当前演示库或覆盖源上传/台账。
2. 采用顺序演练，暂停原业务与模拟网关，避免建设双环境并行平台。为恢复目标创建独立容器/卷、配置、数据目录、Nacos 注册、Redis、RabbitMQ 空间及 ES；启动业务前证明每项依赖属于恢复目标。若复用业务端口，必须证明原进程已停止，不能靠端口相同认定目标正确。
3. 恢复 SQL、Redis、图片、模拟台账；只在恢复副本中处理通知/返回地址与恢复入口的绑定，输出差异清单，不重生成密钥、不改付款金额/交易状态。恢复后所有通知只能到恢复目标。
4. 先只读核对同一交易与库存，再开启恢复目标的补偿。已过期 Session 正常失效、重新登录；到期订单按真实时间处理，不通过改期限“恢复”旧状态。
5. 通过恢复环境页面验证原完成/取消订单、搜索重建，并新建一笔模拟交易走到收货；测试消息重复或重启时库存仍只处理一次，不直接改 SQL 状态。
6. 成功/失败都停止恢复业务和通知重试，再按本次归属清理资源并恢复原模式。核对原备份、配置、密钥和业务数据未被恢复作业覆盖；合法的原环境到期补偿与恢复作业写入分开记录。

验收：恢复目标拥有原交易及新交易证据；付款、库存、事件和图片可关联；恢复环境无法调用原环境服务。端口冲突、错目标或错密钥在危险写入前拒绝；退出后只清理本次资源，原 18 项诊断健康。此阶段的恢复副本允许写入，不能复用只读审计结论代替。
